## Why this matters

`pnpm audit --prod` reports 5 advisories — 3 high, 2 moderate — all in
**transitive dev/build tooling** (not shipped to users), but they trip the
repo's `audit-ci` CI gate, which fails *every* CI job. The repo already pins
some of these via `overrides:` in `pnpm-workspace.yaml`, but those pins are now
**stale**: the advisory's patched version moved past the pinned floor. Bumping
the override floors (and adding two missing ones) clears the gate. Overrides in
this repo do **not** chain or merge — each `name@range` line is independent — so
the fix is to **add** new lines (matching the existing convention of stacking
multiple range lines per package), not edit the old ones.

Advisories to clear (from `pnpm audit --prod`):

| Package    | Vulnerable range        | Patched     | Reaches via                          |
|------------|-------------------------|-------------|--------------------------------------|
| tmp        | `>=0.2.6 <0.2.7`        | `>=0.2.7`   | commitlint → inquirer → external-editor |
| ws         | `>=8.0.0 <8.21.0`       | `>=8.21.0`  | vitest → happy-dom → ws              |
| form-data  | `>=4.0.0 <4.0.6`        | `>=4.0.6`   | nx → axios → form-data               |
| js-yaml    | `>=4.0.0 <4.1.2`        | `>=4.1.2`   | commitlint stack                     |
| markdown-it| `<14.1.2`               | `>=14.1.2`  | typedoc stack                        |

### Convention to match

- 2-space indent, `name@range: ">=x"` format, the list is alphabetically sorted
  by package name. Keep the existing stale lines (they cover narrower ranges)
  and **add** the new wider-range lines next to them in sorted position.
- Quote the version value with double quotes (e.g. `">=0.2.7"`), matching
  neighbors. Caret pins like `^0.2.6` exist but prefer the `">=x"` form used by
  the majority.

Insert these lines into the `overrides:` block, each in its alphabetical slot

- `form-data@...` goes between the `follow-redirects@...` line and the

  `js-yaml@>=4.0.0 <4.1.1` line.

  `minimatch@...` cluster.
- `tmp@<0.2.7` goes directly under the existing `tmp@<0.2.6` line.
- `ws@>=8.0.0 <8.21.0` goes directly under the existing
  `ws@>=8.0.0 <8.20.1` line.

## Why this matters

`pnpm audit --prod` currently reports **1 critical + 4 moderate**
vulnerabilities, none of them suppressed. The repo's own audit gate
(`pnpm run audit`, which runs `audit-ci --config ./audit-ci.jsonc` with
`"low": true` and an **empty allowlist** — see `audit-ci.jsonc:4-7`) therefore
fails today. All five advisories sit in dev-tooling chains (lint-staged,
textlint), not in published packem code, so the fix is pnpm `overrides` — cheap,
contained, and it restores a green security gate.

## Steps

### Step 1: Confirm patched versions

Run `pnpm audit --prod` and read the "Patched versions" row for each advisory.
Expected: `shell-quote` → `>=1.8.4` (if different, use what the audit output
says) and `hono` → `>=4.12.21`.

**Verify**: audit output lists exactly the 5 advisories described above (1
critical shell-quote, 4 moderate hono). If it lists different/additional ones,
STOP and report.

### Step 2: Add the overrides

In the `overrides:` map of `pnpm-workspace.yaml`, add two entries matching the
existing style and sort position:

```yaml
    "shell-quote@<=1.8.3": ">=1.8.4"
    hono@<4.12.21: ">=4.12.21"
```

(`hono` sorts between the existing alphabetical entries; keys with special
characters like `@`/`<`/`>` may need quoting — match how neighboring entries
are quoted, and use the patched versions confirmed in Step 1.)

**Verify**: `pnpm install` → exit 0 and `git diff --stat` shows only
`pnpm-workspace.yaml` + `pnpm-lock.yaml` changed.

### Step 3: Prove the gate is green

**Verify**:
1. `pnpm audit --prod` → no critical and no moderate findings remain.
2. `pnpm run audit` → exit 0.

### Step 4: Sanity-check the overridden tools

The overrides rewrite transitive deps of lint-staged and textlint; make sure
both still load.

**Verify**: `pnpm exec lint-staged --version` → exit 0;
`pnpm exec textlint --version` → exit 0.
